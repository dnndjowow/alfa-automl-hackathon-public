## 2. Исправления по каждому замечанию

### F20 — неверная доля фонового класса при одинаковых вероятностях

**Было:** `p >= quantile(p, 1-share)` включает весь блок равных вероятностей. При постоянных p все строки становятся фоном даже при оценке доли, близкой к нулю.

**Стало:** выбирается ровно `round(share × n)` строк по убыванию p. Равенства разрешаются стабильно по исходному порядку строк. Для нулевого количества маска пустая; для n — полная.

**Реальное воспроизведение:** LightGBM, 600 строк train, 50 одинаковых строк test, adversarial AUC 1,0. При EM-доле около **1,6e−10** до исправления было **50/50** фоновых меток, после — **0/50**. Также проверены промежуточная доля, выбор максимальных p и случаи 0/n.

Это исправление может менять строки на границе выбора фона. Побитовое совпадение прежних public-прогнозов не обещается; качество нужно повторно измерить после вливания.

### F21 — сохранение probability-output

**Было:** проверялось только, что метрика считается по меткам. При Macro F1 и шаблоне с вероятностями новый шаг передавал в сборщик `proba=None`; probability-колонки копировались из sample_submission и затирали готовый результат модели.

**Стало:** до reserve и detector проверяется фактический формат. Разрешён один столбец меток цели либо допустимого одиночного алиаса. Explicit `proba` и несколько колонок классов пропускаются, в том числе при `auto` и принудительном `label`.

**Проверено:** публичная цепочка `set_task → evaluate → finalize → two_stage`. Для probability/auto-шаблонов готовый CSV сохраняется побайтно, metadata `written` остаётся прежним, detector и новый predictor не запускаются. Положительный путь с алиасом `prediction` и составным ID `account + period` работает с настоящими моделями и сохраняет порядок обоих ID.

### F22 — применение только для Macro F1

**Было:** веса conditional-модели подбирались по Macro F1 даже при primary=accuracy. В изоляционном тесте на фиксированных корректных вероятностях реальный оптимизатор весов улучшал Macro F1, снижая accuracy **0,9578 → 0,9098**. Это контрпример целевой функции, не измеренная потеря public score настоящими моделями.

**Стало:** ядро, reserve и финальный шаг разрешают только canonical `f1_macro`. Алиас `Macro F1` поддержан. Accuracy, balanced accuracy, weighted F1, logloss и неизвестная/отсутствующая метрика пропускаются. Для отсутствующей основной метрики ядро возвращает явную причину и заметку.

Таким образом, вариант схемы ограничен той метрикой, для которой его принимали по экспериментам. Нового подбора весов под другие метрики не добавлено.

### F23 — общий бюджет и сохранение старого ответа

**Было:** detector обучался до проверки остатка времени. В ядре его стоимость не вычиталась из бюджета следующих стадий. Даже при исчерпанном deadline могли запускаться новые обучения.

**Стало:**

- В интеграции формат, метрика, наличие фона, остаток времени и оценка стоимости проверяются до detector.
- Detector и финальная схема делят одни 80% доступного остатка. Потраченное на detector вычитается перед вызовом ядра.
- В ядре используется общий монотонный deadline; квоты пересчитываются перед каждой следующей стадией из фактического остатка.
- Есть проверки после подготовки данных, обучения, предсказания и постобработки; detector проверяет время также на итерациях LightGBM.
- Неполный detector и слишком поздний результат не записываются поверх готового CSV. Проверка есть после результата модели и после сборки frame, перед writer.

**Проверено:** нулевой бюджет не вызывает detector; detector, израсходовавший бюджет, не запускает следующие стадии; квоты уменьшаются; timeout внутри реального LightGBM не выдаёт частичный AUC. Искусственный сдвиг монотонных часов после настоящего ML-результата или сборки frame оставляет CSV и `written` прежними, writer не вызывается.

Остановка **кооперативная**. Одна уже начатая операция подготовки/предсказания может перейти deadline до следующей проверки. Жёсткого process timeout этот пакет не добавляет.

### F24 — корректный пропуск регрессии

**Было:** `_resolve_task(profile, 'classification')` принудительно выбирал классификацию; проверка regression skip была недостижима.

**Стало:** внешнее семейство задачи определяется из profile без принудительного override. Classification задаётся только внутренним подзадачам после внешней проверки.

**Проверено:** регрессия с несколькими числовыми значениями и частым нулём теперь даёт `skipped/applied=False` до detector и обучения, как при primary=rmse, так и при отсутствии primary. Раньше получались соответственно error и ошибочное применение классификации. Текущий агент и до этого имел отдельную multiclass-защиту; исправление закрывает публичный API ядра.

## 3. Изменение контракта shift_check

Добавлен последний optional аргумент `time_budget=None`. Прежние позиционные аргументы сохранены.

| Результат | Поля |
| --- | --- |
| Завершённая проверка | `status='ok'`, `complete=True`, числовой `auc`, `shifted`, `seconds` |
| Исчерпан бюджет | `status='skipped'`, `complete=False`, `auc=None`, `shifted=False`, `reason`, `seconds` |

Незавершённый detector нельзя трактовать как измеренный AUC около 0,5 или как достоверное отсутствие сдвига. Его не следует сохранять/передавать как завершённую проверку. `fit_predict_two_stage` в этом случае возвращает `skipped/applied=False`, без нового `pred`. Старый формат заранее рассчитанного `check={'auc': ..., 'shifted': ...}` поддержан тестом.

1. Влить обновлённую ветку интеграции, сохраняя свои новые изменения. При обычном remote `origin`:

