# Мультикласс: почему F1 застрял на 0.53 — сдвиг train/test

Для Ивана · от Юры · 25.10.2026, 16:50 МСК

## Коротко

1. **Главная причина низкого Macro F1 — признаки в test распределены не так, как в train.** Модель отличает строки train от строк test с AUC **0.91**. Даже внутри одного класса это 0.84–0.95.
2. Из-за этого **CV завышен на 0.08**: на валидации 0.61, по скрытым ответам 0.53. На этой задаче выбор моделей по CV почти слепой.
3. **Главная потеря — Normal → Fuzzers: 4 740 из 18 500 строк Normal (25%).** На втором месте Normal → Analysis (541) и Exploits/DoS → Backdoor (482 и 442).
4. Это объясняет, почему не помогли веса классов и коррекция приоров: они исправляют доли классов, а главная беда — сдвиг самих признаков.
5. План проверок в ядре — ниже. Итоги с цифрами — до 22:00, как договорились.

## Сдвиг train/test

**Adversarial validation:** LightGBM учится отличать строку train от строки test, 5 фолдов.

| Что сравниваем | AUC | Главные признаки |
| --- | --- | --- |
| весь train против всего test | **0.907** | `ct_dst_src_ltm`, `ct_dst_sport_ltm`, `ct_srv_src`, `sbytes`, `proto`, `ct_src_ltm`, `ct_srv_dst`, `smean` |
| Normal train против Normal test | 0.919 | `dbytes`, `sttl`, `ct_dst_src_ltm`, `sbytes` |
| Fuzzers train против Fuzzers test | 0.954 | `ct_dst_src_ltm`, `ct_srv_dst`, `ct_srv_src`, `ct_src_dport_ltm` |
| Exploits train против Exploits test | 0.837 | `ct_src_ltm`, `ct_srv_src`, `ct_dst_src_ltm`, `proto` |
| DoS train против DoS test | 0.938 | `ct_src_ltm`, `ct_srv_src`, `ct_dst_src_ltm`, `proto` |

- Сильнее всего сдвинуты **счётчики соединений `ct_*`**. Это число похожих соединений в окне времени, и они зависят от того, какой трафик шёл в момент записи. Модель запомнила их значения из train, а в test они другие: обычный Normal выглядит как Fuzzers.
- **Доли классов тоже сдвинуты:** Normal 0.319 → 0.449, Exploits 0.190 → 0.136, Fuzzers 0.104 → 0.074. Твоя коррекция приоров (0.527 против 0.520) лечила как раз это. Эффект небольшой, потому что основной сдвиг — в признаках.
- **Дубликаты:** копия в train есть у 8.6% строк test. F1 на этих строках 0.38, на остальных 0.54. У 10.7% строк test внутри test есть одинаковые строки с разными ответами.
- **Потолок для ориентира:** если на каждую группу одинаковых строк test давать лучший ответ, Macro F1 был бы 0.78. Запас большой.

## Что проверяю в ядре (до 22:00)

Все правила включаются **только при сильном сдвиге train/test** (по adversarial AUC). На задачах со случайным разбиением, в том числе KDD и covertype, сдвига нет, и ядро ведёт себя как сейчас.

1. **Убрать самые сдвинутые признаки:** ядро само находит признаки, по которым train отличается от test.
2. **Веса строк train по похожести на test** (importance weighting): похожие на test строки весят больше.
3. **Валидация на самых «тестоподобных» строках train:** чтобы CV был честнее и выбор моделей перестал быть слепым.
4. Твои идеи: `custom_stopping` для XGBoost и CatBoost без остановки по TotalF1 — сравню на тех же правилах. CatBoost — на PC.

Приём по твоему правилу: лучше на публичном мультиклассе по скрытым ответам, на 2–3 seed, **и** не хуже на KDD (Macro F1) и covertype (logloss). Если пройдёт — коммит в `yuri/a02-ml-core` и замер «до/после» в `docs/STATUS_YURI.md`.
