## 2. Регрессия (WiDS, RMSE, меньше — лучше)

### 2.1. Где ошибка у агента f350a0c (офлайн, без LLM)

| | RMSE |
| --- | --- |
| Все строки test | **30.85** |
| Известные здания (79% строк) | 20.31 |
| Новые здания (4 655 строк) | **54.89** — 66% квадрата ошибки |

- Ключ здания: `floor_area, year_built, building_class, facility_type`.
- 1% худших строк даёт 68% квадрата ошибки: редкие очень большие значения.
- Подбор «похожего здания» (штат, тип, год, площадь ±2%) нашёл пару только для 351 из 4 655 новых, RMSE на них 77 — бесполезно.

### 2.2. Опыт: отдельные модели для новых зданий

Стенд — XGBoost depth 11, log1p, ядро `train_eval → rounds_from → fit_predict`, валидация по годам. Две проверки: честная (учимся на годах 1–4, проверяем год 5) и контрольная (годы 1–5 → год 6, скрытые ответы).

- **A** — все строки, с признаками здания из прошлых лет (как агент).
- **C** — все строки, без признаков здания.
- **B** — только строки первого появления здания, без признаков здания.

| Вариант | Год 5: новые | Год 6: все | Год 6: новые |
| --- | --- | --- | --- |
| A | 60.50 | 32.17 | 57.01 |
| C | 61.38 | 38.70 | 57.43 |
| B | 60.01 | 44.47 | 58.92 |
| **A, на новых пополам A и C** | **60.00** | **≈ 31.95** | **56.42** |

- **Смесь A+C на новых зданиях** — единственное, что помогает в обеих проверках: на годе 5 и на годе 6. Выигрыш по общему RMSE ≈ 0.2.
- Модель A у меня (32.17) хуже агента (30.85), поэтому в агенте эффект может быть другим. **Не проверено.**

### 2.3. Опыт: поправка масштаба (калибровка log1p) — отклонено

- Множитель «правда / прогноз» для новых зданий на годе 5 — **0.876**, на годе 6 — **1.151**: направление каждый год разное.
- Множитель с года 5, перенесённый на год 6, ухудшает: 32.17 → **33.18**.
- Для известных ×1.041 дал −0.12, но при таком разбросе не доверяем.
- Ранее (простой XGB): линейная калибровка по OOF 38.70 → 38.43, умножение на отношение средних → 38.33. Это тот же эффект масштаба, и он нестабилен.

### 3.3. Честные способы — все отклонены

| Способ | Macro F1 | Вывод |
| --- | --- | --- |
| Текущая схема (EM доли фона) | **0.5423** | лучшая |
| Доля фона: CC / PCC / ACC / PACC | 0.5390 / 0.5409 / 0.5413 / 0.5422 | все оценивают долю в 0.34–0.37, EM уже лучший |
| EM-доли атак на test (поправка на сдвиг долей, Saerens) | 0.4805; с весами 0.4946 | сильно хуже |
| Веса классов по OOF, взвешенному по схожести с test (adversarial p/(1−p), 4 варианта) | 0.5330–0.5390 | хуже |

- Недооценка доли фона идёт не от метода, а от самих вероятностей: из-за сдвига train/test (AUC 0.90) модель принимает часть нормального трафика test за атаки.
- Искусственный подъём доли фона ×1.2 даёт 0.5485, но множитель подобран по ответам public — это подгонка, не берём.
- **Урок:** при взвешивании по схожести с test проверка внутри train показывала прирост +0.03…+0.05, а на test стало хуже. При сильном сдвиге взвешенной проверке внутри train доверять нельзя.
