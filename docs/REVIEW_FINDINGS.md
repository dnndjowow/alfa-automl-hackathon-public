## Как воспроизводить

- **Данные.** Чужие задачи в формате платформы: `python tests/external_tasks.py build`, затем `python tests/external_tasks.py run [имя]`. Это 12 задач из OpenML/scikit-learn и зеркал Kaggle; скрытые ответы лежат в `data/external/_truth/`.
- **Синтетика.** Маленькие задачи в тестах собираются через `tests/synth.make_task(tmp, kind=..., target=..., ...)`.
- **Снипеты** ниже рассчитаны на запуск из корня репозитория: `.venv/bin/python -c "..."`.

**Y1. «NA» как строка.** Воспроизведение: регрессия на 3000 строк, в признаке `x` 5% значений «NA», в таргете 10 строк «NA».

```text
profile: task multiclass ('метрика rmse указывает на regression, а данные однозначно — classification; выбраны данные')
x kind: categorical
train_eval(task_type="regression") -> error: could not convert string to float: 'NA'
если «NA» только в признаке: CV RMSE 3.04 (x — категория) против 0.71, если читать «NA» как NaN
```

Исправление: после чтения проверить каждый object-столбец. Если после замены `{NA, N/A, NaN, null, None, ?, -}` на NaN не меньше 95% значений разбираются как числа, привести столбец к числу. Для таргета делать это всегда. В той же функции стоит обработать строку из пробелов (`" "`, Kaggle Telco `TotalCharges`): сейчас столбец превращается в категорию с 4631 значением. На Telco это ничего не стоит, потому что информацию дублируют `tenure × MonthlyCharges`, но в общем случае потеря реальна.

**Y2/Y3. Метрика.** Воспроизведение: `ml_schema.mentioned_metrics(text)["primary"]`.

```text
'Macro F1 — основная метрика соревнования. Accuracy приводится для справки.' -> accuracy
'MAE является основной метрикой; RMSE выводится для справки.'               -> rmse
'Решения ранжируются по ROC AUC (основная метрика). Также считаем logloss.'  -> logloss
'Основная метрика: macro-averaged F1. Accuracy тоже ...'                    -> accuracy
'Метрика — F1-score (macro). Также смотрим accuracy.'                       -> accuracy
'Основная метрика — PR-AUC (average precision).'                            -> roc_auc
'Основная метрика: F1-score.'                                               -> None (бинарного f1 нет в реестре)
```

Последствие: агент оптимизирует и сравнивает модели не по той метрике; при метрике другого семейства меняется и тип задачи.

Исправление:
- искать ближайшее упоминание в обе стороны в пределах предложения;
- расширить шаблоны: `macro\W{0,3}(averaged\W+)?f1`, `f1[\w\s\-]{0,15}\(?macro`;
- исключить `pr[\s_-]*auc` из шаблона roc_auc;
- добавить `r\^?2` и бинарный `f1`.

Агент Ивана умеет бинарные `f1`/`precision`/`recall` по положительному классу (`agent_tools._binary_metric`), а также rmsle/msle/mape/smape. Ядру их дублировать не обязательно, но `mentioned_metrics` должен называть их основными.

**Y4. Даты.** Таргет зависит от дня, test в том же периоде:

```text
дата как категория:   CV RMSE 2.08, test RMSE 1.94
дата как число дней:  CV RMSE 0.32, test RMSE 0.33
```

Если в test ISO-даты позже, чем в train, `suggest_validation` всё равно выбирает `kfold`, потому что `out_of_range` считается только для числовых столбцов.

Исправление: в `TabularPreprocessor.fit` распознавать object-столбцы, у которых `pd.to_datetime(errors="coerce")` разбирает не меньше 95% значений. Превращать их в числа: дни от эпохи, год, месяц, день недели. В `compare_train_test` учитывать их как числовые, чтобы срабатывала временная схема.

**Y5. Год с пропуском.**

```text
int year без NaN     -> dtype int64,   out_of_range 1.0 -> strategy temporal
то же, 6 NaN в train -> dtype float64, out_of_range 1.0 -> strategy kfold
```

Исправление: проверять не dtype, а то, что все непустые значения целые: `(s.dropna() % 1 == 0).all()`.

**Y6/Y7. Параметры от LLM.** Воспроизведение: `train_eval` с этими `params` проходит, а `fit_predict` падает.

```text
{'early_stopping': 20} / {'n_iter_no_change': 20} / {'early_stopping_round': 10}

{'num_trees': 40} / {'n_iter': 40} / {'max_iter': 40}
```

Исправление: в `BoostingModel` убирать из `params` все синонимы числа раундов и ранней остановки. Для CatBoost переводить известные имена (`max_depth`→`depth`, `colsample_bytree`→`rsm`, `reg_lambda`→`l2_leaf_reg`; при `subsample` ставить `bootstrap_type="Bernoulli"`), а остальные отбрасывать с пометкой в `notes`.

### Наблюдения: не дефекты, но влияют на качество

- **Ранняя остановка идёт по метрике библиотеки,** а не по метрике задачи (`multi_logloss` при macro F1, `l2` при MAE). На синтетике f1_macro 0.7325 → 0.7478 с `{"metric": "multi_error"}`; MAE 4.276 → 4.055 с `objective=l1`. LLM может передать это через `params`; в ядре стоит связать метрику задачи с `eval_metric` по умолчанию.
- **`boosting_type="dart"`** отключает раннюю остановку, и фолд тратит весь бюджет. Агент отбрасывает dart.
- **Logloss при классе, которого нет в train-фолде:** вероятность 0, после клипа около 36 на строку. CV-logloss завышается одинаково для всех моделей.

### Проверено, всё в порядке

- **Публичные задачи:** схема, метрика и валидация определяются верно (temporal/group).
- **Устойчивость на странных данных:** профиль не падает на столбцах из одних NaN, bool с пропусками, смешанных типах, ±inf.
- **Производительность:** на 1M × 36 всё укладывается в секунды.
- **Утечек в предобработке нет:** преобразования учатся только на train-части фолда.
- **Модели:** переиндексация отсутствующего класса верна во всех трёх библиотеках; колбэки времени останавливают все три (бюджет 3 с даёт 3.00–3.05 с); `best_iteration` верен.
- **Метрики и OOF:** ориентация бинарного AUC верна; OOF и обратное `log1p` совпадают с пересчётом.
- **Веса классов:** `choose_class_weights` безвреден на шуме (применился в 3 из 20 случаев с приростом около +0.005).
