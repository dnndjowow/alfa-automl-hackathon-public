## Что делать по шагам

1. Разделить служебные поля, цели и признаки по контракту; сохранить исходные имена и типы.

2. Обрабатывать числовые пропуски и категории разрешёнными средствами. Новые категории test не должны ломать transform.

3. Не обучать преобразования на validation/test; не использовать бинарную label как замену attack_cat.

4. Проверить обе задачи, пропуски и новую категорию на небольшой локальной копии. Записать выбранные значения обработки.

## Готово, когда

- [ ] Количество строк и порядок test сохранены.
- [ ] fit вызывается только на обучающей части; transform работает с неизвестными категориями.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».
