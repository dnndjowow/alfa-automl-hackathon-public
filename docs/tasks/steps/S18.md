## Что делать по шагам

1. Зафиксировать split и seed по контракту; для классов использовать стратификацию, если её допускают данные.

2. Считать RMSE в исходной шкале site_eui и Macro F1 по строковым классам attack_cat.

3. Проверить отсутствие пересечений частей, корректное направление метрики и сопоставимость экспериментов.

4. Описать, когда временные/групповые данные требуют другой схемы; не объявлять случайное разбиение универсальным.

## Готово, когда

- [ ] Повтор даёт тот же split и конечную числовую метрику.
- [ ] Схема не использует ответы test и не обучает преобразования на validation.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».
