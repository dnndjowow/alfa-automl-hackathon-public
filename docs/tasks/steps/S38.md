## Что делать по шагам

1. Взять приоритетный список S30/S32 и QA_LOG; сначала исправить ошибки, мешающие запуску/ответу.

2. Не добавлять новые модели и большие функции; проверить пути, категории, метрики и запись ответа.

3. Повторить обе короткие команды на версии для заморозки, приложить результат к исправлениям.

4. К 10:00 передать Ивану/PM коммит и ограничения; далее держать резерв на ошибки полного прогона до 17:00.

## Готово, когда

- [ ] Блокирующие баги закрыты проверкой либо явно вынесены в решение Ивана.
- [ ] Обе короткие команды работают на фиксируемой версии.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».

Пути ожидаемых новых отчётов в карточке — результат задачи, а не обещание, что файлы уже существуют. Секреты и CSV в Git не добавлять.
