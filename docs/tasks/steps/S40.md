## Что делать по шагам

1. Извлечь финальный ZIP в чистый каталог с официальными зависимостями; проверить, что локальные вспомогательные файлы не нужны.

2. Запустить регрессию 10:00–13:00 и классификацию 13:00–16:00, максимум 3 часа на задачу; если есть независимые ресурсы, можно параллельно.

3. Вместе с Максимом фиксировать версии/длительность/ошибки/ответы. Автоматические запуски занимают окно 6 часов, ручная работа PM оценивается в 1,5 часа.

4. При блокере сразу вызвать Ивана/Юру, проверить исправленный путь и оценить время повторения; при угрозе сроку выбрать уже проверенный резерв.

## Готово, когда

- [ ] Обе задачи проверены именно из сдаваемого архива либо явно выбран ранее проверенный резерв.
- [ ] Состав/хеш/версия/команды/длительности и корректность ответов записаны.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».

## Передача и следующий шаг

Ивану — результаты для технической приёмки; PM держит резерв до отправки.

После этой карточки открывается: [S43 — Иван](https://github.com/selecteg12/alfa-automl-hackathon/blob/main/docs/tasks/steps/S43.md)

Технические изменения принимает Иван, комплектность — Егор. Агенту полезно передать [вводную участника](https://github.com/selecteg12/alfa-automl-hackathon/blob/main/docs/team-context/egor.md) и эту карточку; запрос участник составляет сам, человек проверяет выполненную работу. Пути ожидаемых новых отчётов в карточке — результат задачи, а не обещание, что файлы уже существуют. Секреты и CSV в Git не добавлять.
