## Что делать по шагам

1. Открыть MATERIALS и DATA_SETUP; проверить исходный PDF, FAQ, baseline, текущие requirements и две папки данных.

2. Для каждой публичной задачи отметить наличие task.md, train, test, словаря и образца ответа. CSV в Git не добавлять.

3. Выписать недоступные ссылки и противоречия с точным источником; не тратить час на обход одного сбоя.

4. Передать PM короткий список вопросов, разработчикам — удобные ссылки. Затем начать EDA регрессии.

## Готово, когда

- [ ] Каждый важный материал подписан и доступность проверена.
- [ ] Проблемы доступа перечислены отдельно, ML-разработка не ждёт отчёт.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».
