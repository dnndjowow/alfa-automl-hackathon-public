## Что делать по шагам

1. Описать цепочку входные файлы → решение LLM → ML-инструменты → исследование → submission простыми словами.

2. Вставить команды из RUNBOOK, ссылки на проверенные EDA/эксперименты и текущий журнал результатов.

3. Проверить по платформе, требуется ли дополнительное описание/демо; подготовить только обязательные материалы, не начинать отдельный интерфейс.

4. Сверить утверждения с Иваном и PM. Не писать о неподтверждённых возможностях и private-метриках; результаты полного прогона добавит PM после проверки.

## Готово, когда

- [ ] Описание соответствует фактическому коду и командам.
- [ ] У PM есть материалы сдачи и список непроверенных утверждений.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».

## Передача и следующий шаг

PM — готовый текст; Ивану — подтвердить технические утверждения.

После этой карточки открывается: Результат включается в этап и итоговую приёмку.

Технические изменения принимает Иван, комплектность — Егор. Агенту полезно передать [вводную участника](https://github.com/selecteg12/alfa-automl-hackathon/blob/main/docs/team-context/artem.md) и эту карточку; запрос участник составляет сам, человек проверяет выполненную работу. Пути ожидаемых новых отчётов в карточке — результат задачи, а не обещание, что файлы уже существуют. Секреты и CSV в Git не добавлять.
