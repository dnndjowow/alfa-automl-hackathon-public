## Что делать по шагам

1. Выбрать 5–7 фактов, которые влияют на обработку, валидацию или проверку ответов.

2. Для каждого указать источник/измерение, риск и вопрос к Ивану; не выдавать гипотезу за принятое ML-решение.

3. Отдельно отметить сдвиг train/test, пропуски, редкие классы и потенциальную утечку.

4. Передать ссылку Ивану и Юре; записать подтверждённые решения после их просмотра.

## Готово, когда

- [ ] Короткий отчёт связан с воспроизводимыми EDA.
- [ ] Разработчики получили выводы; неподтверждённые рекомендации подписаны.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».

## Передача и следующий шаг

Ивану — подтвердить ML-решения; Юре — применить только согласованные изменения.

После этой карточки открывается: [S27 — Артём](https://github.com/selecteg12/alfa-automl-hackathon/blob/main/docs/tasks/steps/S27.md)

Пути ожидаемых новых отчётов в карточке — результат задачи, а не обещание, что файлы уже существуют. Секреты и CSV в Git не добавлять.
