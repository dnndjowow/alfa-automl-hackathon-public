## Что делать по шагам

1. Реализовать чтение условия и сопутствующей схемы: пути, таргеты, тип задачи, метрика, направление, колонки ответа.

2. Для неоднозначных полей предусмотреть структурированное уточнение через LLM и валидацию результата.

3. Проверить оба публичных task.md и копию с переименованной целью/каталогом.

4. Возвращать понятную ошибку на отсутствующий файл или неподдержанную метрику.

## Готово, когда

- [ ] Регрессия и классификация дают валидный TaskSpec.
- [ ] Переименование цели не требует ручного изменения логики.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».
