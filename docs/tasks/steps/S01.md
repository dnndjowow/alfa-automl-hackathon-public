## Что делать по шагам

1. Прочитать оба task.md, ограничения и baseline; выписать пути, таргет, ID, метрику, направление оптимизации и формат ответа.

2. Описать минимальные TaskSpec, ExperimentConfig и ExperimentResult: качество, время, ошибка, артефакт. Названия структур можно согласовать с текущим кодом.

3. Согласовать с Юрой split/seed, интерфейс train/evaluate/predict и две заполненные схемы для публичных задач.

4. Оставить поля для нескольких целей/вероятностей; неизвестные постановки обозначать явно. Отдать Юре контракт до реализации всех деталей.

## Готово, когда

- [ ] Есть два конкретных примера схемы и договорённые сигнатуры.
- [ ] Нет обязательной привязки всех задач к site_eui или attack_cat.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».
