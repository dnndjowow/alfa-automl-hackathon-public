## Что делать по шагам

1. Сверить результаты двух задач, журнал платформы и оставшиеся баги; выбрать надёжную воспроизводимую версию.

2. Вместе с Юрой повторить короткий проход финальной конфигурации после исправлений.

3. К 10:00 зафиксировать commit SHA и конфигурацию для полного прогона. Дальше принимать только блокирующие исправления с повторной проверкой.

4. Записать в RELEASE_NOTES ожидаемые метрики, ограничения, бюджеты и запасной рабочий архив.

## Готово, когда

- [ ] Финальная версия однозначно определена и воспроизводится.
- [ ] PM получил команду и параметры полного запуска к 10:00.
- [ ] Приложены ссылка на коммит/отчёт, точная команда проверки, фактический результат и ограничения. Статус «На проверке»; после приёмки — «Готово».
