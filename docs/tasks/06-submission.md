# Собрать полный ML-проход и проверку submission.csv

**Ответственный:** Юра  
**Приоритет:** P0 · **Этап:** Первый запуск  
**Контрольная точка:** T0 + 10 часов. Это внутренний ориентир; T0 и официальный дедлайн подтверждает PM.

## Зачем это нужно

Эта задача соединяет части в один работающий сценарий и отвечает за правильный файл. Качество модели бесполезно, если платформа не может прочитать ответ.

## С чего начать

Параллельно с интеграцией реализовать независимую проверку файла по двум известным схемам; затем подключить её к агенту.

Согласования: [#2](https://github.com/selecteg12/alfa-automl-hackathon/issues/2), [#3](https://github.com/selecteg12/alfa-automl-hackathon/issues/3), [#4](https://github.com/selecteg12/alfa-automl-hackathon/issues/4). Прототип и изучение материалов можно готовить параллельно.

## Пошаговое выполнение

1. **Зафиксировать две входные команды.** С Иваном договориться о вызове solution.py с task.md. Команды в будущей инструкции должны ссылаться на реальные локальные пути после подготовки данных.

2. **Соединить весь путь.** Выполнить чтение условия, профилирование, выбор LLM, обучение/оценку и формирование test-предсказаний. Убрать ручные переключения между датасетами.

3. **Собрать таблицу ответа.** Брать id из test в исходном порядке, а предсказания — из того же порядка объектов. Структуру брать из task.md и sample_submission; значения sample не являются правильными ответами.

4. **Реализовать проверку схемы.** Для публичной регрессии: ровно id,site_eui; все предсказания конечные. Для классификации: id,attack_cat; значения принадлежат допустимым строковым классам. Число строк и id совпадают с test, дополнительного CSV-индекса нет.

5. **Сохранять результат надёжно.** Записывать submission.csv в каталог task.md. Проверить файл после записи. Если используется временный файл, корректно заменить им итоговый в том же каталоге; предыдущий рабочий ответ беречь до готовности нового.

6. **Проверить каталоги и повторный запуск.** Запустить из корня репозитория и из другого рабочего каталога. Использовать разные корни задач, чтобы два локальных ответа не перезаписывали друг друга.

7. **Проверить ошибочный вход.** На небольшой локальной копии передать неправильное число предсказаний или неизвестный класс. Валидатор должен сообщить конкретную причину и не принять ответ как успешный.

8. **Передать на приёмку.** Дать Ивану и PM точный коммит, обе команды, время и результаты проверки. Сообщить, какие части ещё временные.

## Минимум для первой версии

Один общий код выдаёт корректный submission.csv на обеих публичных задачах без ручной смены таргета.

## Готово, когда

- [ ] Одна согласованная команда проходит от task.md до корректного submission.csv на каждой публичной задаче.
- [ ] Запуск работает из другого текущего каталога.
- [ ] Иван или PM повторил команду по инструкции без ручных исправлений.

## Как проверить

1. Ожидаемые строки: 22 449 для регрессии и 41 166 для классификации; сверить с фактически скачанным test.
2. id и порядок строк побайтно/по значениям сопоставляются с test; дубликатов и пропусков нет.
3. При ошибке очередного эксперимента ранний проверенный ответ остаётся доступен.

## Что и кому передать

PM: две команды, коммит, путь к каждому ответу и вывод валидатора. Максим получает эти же команды для повторного запуска.

К передаче приложить: ссылку на коммит/PR или отчёт, точную команду проверки, фактический результат и оставшиеся ограничения. Слова «агент написал» сами по себе не подтверждают готовность.

## Типичные ошибки

- Писать submission.csv в текущий каталог вместо каталога task.md.
- Сохранить числовые коды классов вместо строковых меток attack_cat.
