## Пошаговое выполнение

1. **Получить файлы и проверить структуру.** Подготовить локальные данные по DATA_SETUP.md. Вывести имена колонок, размеры train/test и первые строки. Отметить несоответствия описанию; не исправлять их молча.

2. **Надёжно разрешать пути.** Считать базовым каталогом расположение task.md. В публичных задачах от него идут regression/participants/... и multiclass/participants/.... Проверить запуск из другого текущего каталога.

3. **Разделить роли колонок.** Использовать согласованный TaskSpec и фактический словарь: признаки, целевые колонки, идентификаторы. Убедиться, что таргет не попал в X, а порядок строк test сохранён.

4. **Собрать компактный профиль.** Для колонок вывести dtype, долю пропусков, число уникальных значений и несколько примеров. Для таргета регрессии — квантили; для классификации — количество объектов каждого класса.

5. **Реализовать начальную предобработку.** Выбрать простую обработку числовых пропусков и категорий, совместимую с выбранной моделью. Для CatBoost и линейных моделей требования различаются; выбор подтвердить с Иваном. Сервис '-' не превращать автоматически в ошибку данных.

6. **Защитить валидацию.** Обучать imputer, encoder, scaler и аналогичные преобразования только на train-части. Тот же fitted-объект применять к validation/test. Новые категории в test должны обрабатываться предсказуемо.

7. **Проверить изменения схемы.** На небольшой локальной копии проверить пропуск, неизвестную категорию, переименование таргета вместе с описанием и другое расположение папки. Вернуть понятную ошибку, если обязательного файла действительно нет.

8. **Передать готовый интерфейс.** Подключить загрузчик к контракту #1. Описать, что именно возвращается, где хранятся fitted-преобразования и как сохраняется соответствие строк ответа строкам test.

## Минимум для первой версии

Обе публичные задачи читаются, таргет отделён, пропуски и категории не приводят к падению. Сложную генерацию признаков оставить на подтверждённые эксперименты.

## Готово, когда

- [ ] Обе публичные задачи загружаются одинаковым интерфейсом.
- [ ] Переименование колонки или изменение каталога не ломает загрузку при корректном task.md.
- [ ] Преобразования не используют ответы test и не теряют порядок тестовых строк.

## Как проверить

1. На актуальных публичных файлах ожидаются 53 308/22 449 строк для регрессии и 87 670/41 166 для классификации; любые отличия проверить по самим файлам.
2. Порядок и значения id в test не меняются после предобработки.
3. Validation обрабатывается теми же fitted-преобразованиями, что подготовлены на train-части.

## Типичные ошибки

- Обучить encoder на полном train до разделения и получить завышенную локальную метрику.
- Считать id постоянным идентификатором здания или вычислять возраст как Year_Factor - year_built.
