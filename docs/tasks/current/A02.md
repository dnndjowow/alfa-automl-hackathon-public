## Шаги внутри блока

Это ориентир: порядок и техническую реализацию владелец выбирает сам. Дополнительное согласование обычных решений не требуется.

1. Начать с CSV и путей относительно task.md; сохранить ID/порядок test. Согласовать с Иваном один рабочий пример вызова. Не ждать законченного архитектурного документа.

2. Подготовить числа/категории/пропуски, обучая преобразования на train-части split. Собрать компактный профиль для LLM: размеры, типы, пропуски, кардинальности, распределение целей. Ручной EDA Артёма — отдельная помощь, ожидать его не требуется.

3. Самостоятельно выбрать простые модели из разрешённых библиотек для регрессии и классификации. Дать агенту возможность выбрать схему валидации по контексту; для public достаточно корректного воспроизводимого разбиения. RMSE считать в исходной шкале, Macro F1 — по классам.

4. Возвращать метрику, направление сравнения, время, результат/ошибку и предсказания или путь к модели. Не фиксировать site_eui/attack_cat/id как обязательные имена всех будущих задач.

5. Писать валидный ответ рядом с task.md: правильные колонки, количество и порядок строк, допустимые значения, без NaN/inf. Сохранять через временный файл и замену завершённого результата.

6. Вместе с Иваном повторить две общие команды, включая другой текущий каталог. Передать Егору и Максиму версию и команды; достаточно одного общего README/RUNBOOK с реальными примерами.
