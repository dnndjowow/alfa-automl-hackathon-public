# A11. Закрыть блокирующие ошибки и передать финальный pipeline

**Начать:** 24.10 21:00 · **Завершить до:** 25.10 10:00 · **Время:** МСК, 2026 год.

## Шаги внутри блока

Это ориентир: порядок и техническую реализацию владелец выбирает сам. Дополнительное согласование обычных решений не требуется.

1. Взять оставшиеся баги из интеграции/проверок Артёма и Максима. Первым делом закрыть ошибки запуска, метрик и формата ответа.

2. При необходимости самостоятельно проверить 1–2 осмысленных улучшения модели на том же split; сохранить только подтверждённую пользу. Это дополнительная работа после закрытия блокеров.

3. С Иваном повторить обе короткие команды на выбранной версии. Проверить, что переносимая конфигурация работает без ручного изменения цели/метрики.

4. К 10:00 передать SHA/команды/ограничения Егору. После заморозки оставаться доступным для блокирующих ошибок полного прогона; затронутый путь проверять после исправления.

- [ ] В карточке есть ссылка на коммит/артефакт, фактическая проверка и оставшийся блокер/ограничение, если оно есть. Большой отчёт и отдельный созвон не нужны.

## Самостоятельность

Владелец сам выбирает библиотеки из разрешённых, алгоритмы, параметры, имена файлов/функций, тесты и организацию кода. Несовместимое изменение общего вызова согласуется с затронутым участником; новый пакет вне requirements — с организаторами через Егора. Локальные исправления и эксперименты разрешения PM не требуют.

Один активный блок. Статус «В работе» ставится при старте; после выполненной проверки владелец закрывает блок сам. Кросс-компонентный проход проверяют вместе Иван и Юра, релиз — Иван и Егор. Если срок под угрозой, сразу указать готовую часть, причину и нужный вход; продолжить независимую работу.
