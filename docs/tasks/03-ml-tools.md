## Зачем это нужно

Нужны исполняемые ML-инструменты: они действительно обучают модель и возвращают измеренное качество. Агент будет выбирать их конфигурации и анализировать результат.

## С чего начать

Использовать контракт #1 и загрузчик #2. Первую простую модель можно поднять на небольшой подвыборке до завершения общего агента.

Согласования: [#1](https://github.com/selecteg12/alfa-automl-hackathon/issues/1), [#2](https://github.com/selecteg12/alfa-automl-hackathon/issues/2). Прототип и изучение материалов можно готовить параллельно.

## Пошаговое выполнение

1. **Зафиксировать один воспроизводимый эксперимент.** Выбрать seed и индексы validation, согласованные с Иваном. Сохранить их или способ их получения. На этой же схеме сравнивать последующие конфигурации.

2. **Поднять простой регрессионный вариант.** Обучить разрешённую модель для site_eui. Получить предсказания validation и посчитать RMSE на исходной шкале таргета. Если использовано преобразование таргета, выполнить обратное преобразование перед основной метрикой.

3. **Поднять классификационный вариант.** Обучить модель для attack_cat, сохранить соответствие строковых классов. Посчитать Macro F1 и качество по классам; Accuracy вывести дополнительно.

4. **Проверить базовую здравость.** Сравнить с простым локальным ориентиром: среднее для регрессии, частый класс для классификации. Это внутренняя проверка кода, а не скрытый baseline организаторов.

5. **Обернуть обучение в инструмент.** Принимать конфигурацию, описание задачи и бюджет. Возвращать результат по контракту #1: метрику, длительность, артефакты и статус. Сохранить лучший завершённый вариант.

6. **Ограничить ресурсы.** Явно задать допустимое число потоков и управлять длительностью обучения. Проверить поведение при маленьком бюджете; все модели должны работать на CPU.

7. **Сделать финальное обучение и predict.** После выбора конфигурации обучить финальную модель на доступном train и получить test-предсказания без использования ответов test. Подготовить вероятности только если их требует конкретная задача.

8. **Передать агенту.** Дать Ивану минимальный пример вызова и оба ExperimentResult. Проверить совместный запуск инструмента из агента.

## Минимум для первой версии

По одному рабочему подходу для регрессии и классификации, реальные локальные метрики и test-предсказания.

## Готово, когда

- [ ] На обеих публичных задачах получены конечные числовые метрики локальной валидации.
- [ ] Инструмент возвращает согласованный результат и понятную ошибку при неудаче.
- [ ] Есть команда воспроизведения и ссылка на коммит.

## Как проверить

1. RMSE конечен и считается после возврата в исходные единицы; Macro F1 находится в допустимом диапазоне.
2. Повтор с тем же seed даёт сопоставимый результат; отклонения и источники случайности описаны.
3. Есть измеренное время и понятный результат при ошибке обучения.

## Что и кому передать

Ивану: интерфейс вызова, две конфигурации, локальные метрики и команды. Юре в #6: модели и test-предсказания в согласованном виде.

К передаче приложить: ссылку на коммит/PR или отчёт, точную команду проверки, фактический результат и оставшиеся ограничения. Слова «агент написал» сами по себе не подтверждают готовность.

## Типичные ошибки

- Оптимизировать Accuracy при основной Macro F1.
- Выдавать локальную метрику за public score: значения baseline организаторов скрыты.
