# Вводная: Юра

**Роль участника:** Основной разработчик ML-инструментов и обработки данных. Это контекст проекта и ответственности, который участник может передать своему агенту.

GitHub: [dnndjowow](https://github.com/dnndjowow). Соответствие всей команды и доступы: [ACCESS](https://github.com/selecteg12/alfa-automl-hackathon/blob/main/docs/ACCESS.md).

## Что команда делает

Пять человек готовят автономного AI-агента для разработки табличных ML-моделей. На вход подаётся task.md и сопутствующие файлы. Агент понимает постановку, выбирает обработку/модели, запускает эксперименты, оценивает их, улучшает решение и сохраняет submission.csv рядом с task.md. Решения LLM должны реально влиять на действия.

Публично доступны регрессия site_eui с RMSE и классификация attack_cat с Macro F1. Private-задачи могут отличаться, поэтому обязательные имена публичных целей не зашиваются для всех запусков.

## Сроки и состояние

Старт **23.10.2026 20:00 МСК**, финальное решение **25.10.2026 20:00 МСК**. Первый сабмит — 24.10 до 15:00. Новые функции замораживаются 25.10 в 10:00, полная репетиция идёт до 16:00, техническая приёмка/отправка — к 17:00, проверка статуса — до 19:30.

## Зона ответственности

Второй большой технический блок: загрузка данных, предобработка, автоматический профиль для LLM, валидация, метрики, обучение, предсказания, проверка submission.csv, интеграция с контроллером и исправление сбоев.

Ориентир: 11 карточек, около 15.5 ч активной работы. Ожидание автоматических запусков учитывается отдельно.

## Ожидаемые результаты

- Повторяемый pipeline по контракту Ивана для обеих публичных задач с поддержкой изменяемой схемы входа.
- Инструменты train/evaluate/predict с реальными RMSE и Macro F1, временем и понятными ошибками.
- Компактный автоматический профиль данных для решений агента; отдельный ручной EDA выполняет Артём.
- Валидный submission.csv рядом с task.md с исходным порядком ID и проверкой схемы.
- Общая команда полного запуска, ограниченные ресурсы и сохранение рабочего результата при сбоях.

## Связи с командой

- Иван владеет общим контрактом, LLM-контроллером, схемой сравнения и выбором моделей. Загрузку можно начать сразу, сверив интерфейс после его первой карточки.
- Артём передаёт проверенные свойства данных и вопросы. Самостоятельное исследование ради отчёта не дублируется; runtime-профиль нужен отдельно.
- Егор обеспечивает окружение и сборку. К 24.10 14:00 ему нужны рабочий SHA, две команды, ожидаемые файлы и ограничения.
- Максим получает готовые команды и ожидаемое поведение; его воспроизводимые ошибки возвращаются Юре/Ивану через карточки.

## Важные границы

Обучаемые преобразования подбираются только на train-части соответствующего split. Порядок test и ID сохраняется отдельно. Ответы test не используются, sample_submission служит схемой. Изменения контракта согласуются с Иваном. Полный EDA и LLM-контроллер имеют других владельцев.

Общие ограничения: Python 3.12, CPU-only, 8 CPU / 32 GB RAM / 30 GB диска на задачу, до 3 часов на задачу. Платформа использует корневые .py и официальный requirements.txt из ZIP до 100 МБ. Данные/ключи/модели в Git не добавляются. API и модель — только выданные организаторами; несовпадение mcp в baseline/requirements разбирают Иван и Егор до выбора зависимости.
