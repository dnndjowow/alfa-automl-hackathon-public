# Вводная: Максим

**Роль участника:** Воспроизведение запусков, проверки по чек-листу и отчёты о сбоях. Это контекст проекта и ответственности, который участник может передать своему агенту.

GitHub: [osin1500maxim](https://github.com/osin1500maxim). Соответствие всей команды и доступы: [ACCESS](https://github.com/selecteg12/alfa-automl-hackathon/blob/main/docs/ACCESS.md).

## Что команда делает

Пять человек готовят автономного AI-агента для разработки табличных ML-моделей. На вход подаётся task.md и сопутствующие файлы. Агент понимает постановку, выбирает обработку/модели, запускает эксперименты, оценивает их, улучшает решение и сохраняет submission.csv рядом с task.md. Решения LLM должны реально влиять на действия.

Публично доступны регрессия site_eui с RMSE и классификация attack_cat с Macro F1. Private-задачи могут отличаться, поэтому обязательные имена публичных целей не зашиваются для всех запусков.

## Сроки и состояние

Старт **23.10.2026 20:00 МСК**, финальное решение **25.10.2026 20:00 МСК**. Первый сабмит — 24.10 до 15:00. Новые функции замораживаются 25.10 в 10:00, полная репетиция идёт до 16:00, техническая приёмка/отправка — к 17:00, проверка статуса — до 19:30.

При подготовке вводной в репозитории были планирование, исходные материалы и baseline организаторов; рабочий solution.py ещё предстоит сделать. Реальное состояние всегда определяется текущим кодом, Issue и статусом на [доске](https://github.com/users/selecteg12/projects/2). Упомянутые ниже новые отчёты — ожидаемые результаты, а не уже готовые файлы.

## Зона ответственности

Проверка ссылок и окружения, независимое повторение готовых команд, проверка выходных CSV, повтор исправленных ошибок, аудит финального архива и сбор фактических результатов длинных прогонов.

Ориентир: 6 карточек, около 7.5 ч активной работы. Ожидание автоматических запусков учитывается отдельно.

## Ожидаемые результаты

- QA_LOG: дата МСК, SHA, окружение, точная команда, ожидание/факт, код завершения, длительность и лог без секретов.
- На каждый баг — короткие шаги воспроизведения, ожидаемый и фактический результат, ссылка на версию и серьёзность.
- Проверка двух submission: место сохранения, строки/порядок ID/колонки, отсутствие пустых значений, допустимые классы.
- Аудит ZIP: размер, корневые файлы, актуальные зависимости, отсутствие лишних данных/моделей/ключей.
- Итоговый список «проверено / не проверено / блокирует» по финальным прогонам.

## С чего начинается работа

В 20:00 проверить ссылки и подготовить шаблон отчёта. После инструкции окружения в 23:00 повторить подготовку. Полные короткие команды обеих задач ожидаются 24.10 в 14:00; до этого успешный ML-запуск не заявляется.

Полезно сначала проверить актуальную ветку, исходные файлы и принятый контракт. Если INTERFACES, RUNBOOK или другой ожидаемый файл ещё не создан, это вход от владельца соответствующей карточки; предположения согласуются до интеграции.

## Связи с командой

- Егор передаёт версию, архив и инструкцию; ему сразу сообщаются проблемы доступа/окружения/упаковки.
- Юра даёт готовые команды запуска и валидатор ответа, получает воспроизводимые сбои pipeline.
- Иван получает технические блокеры и подтверждает готовность финальной версии.
- Артём может использовать проверенные результаты для описания проекта, если есть ссылка на SHA/лог.

## Важные границы

Новые модели, архитектура и изменения ML-стратегии не входят в эту роль. Инструкции повторяются точно; при сбое сохраняется исходная команда, а исправление не скрывается. Если входа/команды нет — статус «не проверено» с причиной. Финальную готовность и выбор архива подтверждают Иван и Егор.

Общие ограничения: Python 3.12, CPU-only, 8 CPU / 32 GB RAM / 30 GB диска на задачу, до 3 часов на задачу. Платформа использует корневые .py и официальный requirements.txt из ZIP до 100 МБ. Данные/ключи/модели в Git не добавляются. API и модель — только выданные организаторами; несовпадение mcp в baseline/requirements разбирают Иван и Егор до выбора зависимости.
