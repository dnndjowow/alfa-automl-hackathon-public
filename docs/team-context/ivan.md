## Что команда делает

Пять человек готовят автономного AI-агента для разработки табличных ML-моделей. На вход подаётся task.md и сопутствующие файлы. Агент понимает постановку, выбирает обработку/модели, запускает эксперименты, оценивает их, улучшает решение и сохраняет submission.csv рядом с task.md. Решения LLM должны реально влиять на действия.

Публично доступны регрессия site_eui с RMSE и классификация attack_cat с Macro F1. Private-задачи могут отличаться, поэтому обязательные имена публичных целей не зашиваются для всех запусков.

## Связи с командой

- Юра реализует загрузку, преобразования, обучение, оценку и запись ответа. Иван задаёт контракт и стратегию, помогает снять ML-блокеры; интеграция выполняется вместе.
- Артём отвечает за EDA. Его факты помогают выбору обработки и валидации; технические выводы подтверждает Иван. Загрузка и обучение могут идти до завершения EDA.
- Егор отвечает за окружение, упаковку, координацию и отправки; ему нужны конкретные SHA, команды и решение о готовности.
- Максим повторяет готовые проверки и описывает сбои; техническую готовность финала подтверждает Иван.

## Важные границы

Универсальность важнее привязки к двум публичным именам колонок. Полная поддержка всех возможных private-постановок за 48 часов не обещана: проверенное покрытие и ограничения должны быть явными. Генерация произвольного кода моделью необязательна; готовые инструменты допустимы при реальном влиянии LLM.

Общие ограничения: Python 3.12, CPU-only, 8 CPU / 32 GB RAM / 30 GB диска на задачу, до 3 часов на задачу. Платформа использует корневые .py и официальный requirements.txt из ZIP до 100 МБ. Данные/ключи/модели в Git не добавляются. API и модель — только выданные организаторами; несовпадение mcp в baseline/requirements разбирают Иван и Егор до выбора зависимости.
