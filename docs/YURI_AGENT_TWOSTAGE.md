**Почему работает:** главная ошибка агента — Normal → Fuzzers (4 740 из 18 500 строк). Доля Normal в test (0.45) выше, чем в train (0.32). Схема сначала решает «фон или атака» с поправкой на долю фона в test (EM), а потом выбирает тип атаки среди не-фона.

### 4.1. `two_stage_reserve(session)` — резерв времени

Вызывается в `main()` сразу после `session.write_constant()`:

```python
reserve = two_stage_reserve(session)
if reserve:
    session.deadline -= reserve   # возвращается перед шагом two_stage
```

- Резерв = 20% оставшегося времени, если по паспорту задача подходит: основная метрика по меткам, `resolve_schema` проходит, один таргет, классов ≥ 3, самый частый ≥ 30%, `shift_check` → AUC > 0.8.
- Иначе 0, и агент работает ровно как раньше. Любое исключение → 0 и запись в журнал.
- **Зачем:** без резерва запасная политика и `tune_more` заполняют всё время. Первый чистый прогон: три CatBoost по 4–10 мин, XGBoost не дошёл, шаг пропущен — «нужно ≈864 с, осталось 423 с».

### 4.2. `two_stage(session)` — сам шаг

Порядок в `main()`:

```python
guarded(ensure_final, session)
guarded(stabilize, session)
session.deadline += reserve
guarded(two_stage, session)   # при включении записанный run_id = None, и polish ответ не перетирает
guarded(polish, session)
```

Условия — все сразу:
- `setup["task_type"] == "multiclass"`, один таргет, `metric_obj.needs == "labels"`;
- уже записан ответ обученной модели (`written.run_id`);
- `shift_check(setup["split"].X_train, setup["split"].X_test)` → AUC > 0.8 (по текущему набору признаков агента);
- время: `1.5 × (оценка LightGBM + оценка XGBoost)` из твоих запусков ≤ `0.8 × остаток`, остаток ≥ 300 с. Если XGBoost не оценивался, за его время берётся 2 × LightGBM.

Действия:
1. `ml_tools.fit_predict_two_stage(setup["split"], setup["profile"], models=("lightgbm", "xgboost"), n_jobs, seed, time_budget=0.8 × остаток, check=...)`.
2. При `ok` — `session._assemble(setup, {таргет: (pred, None, классы)})` (столбцы и порядок id шаблона) → `agent_tools.write_submission(...)`.
3. `session.written = {"run_id": None, "model": "two_stage", "score": None, "replaced": <прежний written>, "two_stage": {background, share_train, share_test, auc}}`.
4. При `skipped` / `error` — только строка в журнале `[two_stage] …`, прежний ответ остаётся на диске.

Весь шаг под `guarded`: сбой не лишает уже записанного ответа.

## 6. Что не проверено и риски

- **18 внешних задач на `b09a98e`** — твой сервер. Ожидание: шаг и резерв включаются только при сдвиге и фоновом классе; на остальных `shift_check` вызывается, только если метрика по меткам и есть фон (3–4 с).
- **Прогон с LLM:** шаг стоит после диалога и запасной политики, LLM-путь не меняет. При включении резерв на 20% уменьшает время LLM.
- **Время на платформе:** оценка грубая. Если не хватит — шаг пропускается, а не обрывается. Внутри схемы `time_budget` делится на 4 цикла; при нехватке модели останавливаются по времени, и ответ может быть слабее — поэтому есть порог по оценке.
- **Только метки:** для задач с ответом-вероятностями шаг не включается.
