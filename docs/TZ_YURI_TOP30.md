## Твоя зона: мультикласс (и вообще классификация со сдвигом train/test)

Что уже не помогло (таблица в `docs/STATUS_YURI.md`, 19:05): удаление сдвинутых признаков, веса строк, регуляризация, смеси через ядро,
приоры (EM), веса классов сверх текущих, дубликаты, `target_mean` по `tcprtt`.

Порядок работ — от дешёвого к дорогому. Каждый пункт — отдельный замер «до/после».

1. **Ранговая нормализация сдвинутых признаков** (твоя идея 1). Ранг внутри своего файла: train отдельно, test отдельно.
   Включается при adversarial AUC > 0.8. Проверь также квантильную нормализацию к общему распределению.
2. **Псевдоразметка test** (твоя идея 2):
   - 1–2 раунда; в обучение идут только строки с уверенностью выше порога класса;
   - порог подбирается так, чтобы на «тестоподобной» части train точность псевдометок была ≥ 0.95;
   - в метрику по train псевдостроки не входят.

   Отдельно проверь «мягкий» вариант: псевдостроки с весом 0.3–0.5.
3. **Порог «Normal против остальных» под сдвиг.** Главная потеря — Normal → Fuzzers (4 740 строк).
   - Двухступенчатая схема: бинарная модель «норма/атака» + мультикласс по атакам. Порог бинарной модели калибруется так, чтобы доля
     «нормы» в предсказании test совпала с оценкой этой доли (EM по test или доля из бинарной модели на test).
   - Это общий механизм для «класс-фон + редкие классы».
   - Сравни с текущими весами классов из `choose_class_weights`.
4. **CatBoost без остановки по TotalF1** и **`custom_stopping` для XGBoost** на 3 seed (твой PC). Если поможет — в смесь.
5. **kNN-признаки по объединённому train+test без меток.** Расстояние до ближайших строк test и train, плотность. Это помогает модели
   «понять», что строка из области test. Только если 1–3 ничего не дали.
