# Исправления two-stage по ревью F20–F24

Изменения ядра: `b119dd6`. Ветка `yuri/agent-twostage` содержит это ядро и защиту интеграции. Исправляются только F20–F24; прежние F01/F02/F06/F07/F12 остаются отдельными задачами.

| Замечание | Исправление | Проверенный результат |
| --- | --- | --- |
| F20 | Ровно round(share × n) фоновых строк по стабильному рангу, включая 0/n и равные вероятности | Реальный LightGBM: при EM-доле около 1,6e−10 фоновых меток стало 0/50 вместо 50/50 |
| F21 | Перед reserve/обучением проверяется фактический формат: один столбец меток цели/алиаса; proba и шаблоны по классам пропускаются | При proba и auto прежние вероятности и metadata ответа сохраняются без запуска detector |
| F22 | Ядро и интеграция разрешают только canonical Macro F1; другие/неизвестные метрики пропускаются с причиной | Accuracy больше не получает веса, выбранные по Macro F1; алиас Macro F1 поддержан |
| F23 | Проверки времени/стоимости до detector, общий deadline, бюджет detector и пересчёт остатка перед стадиями | Истёкший бюджет не запускает обучение; неполная проверка сдвига и поздний результат не заменяют CSV |
| F24 | Семейство задачи определяется из profile без принудительного classification | Регрессия с частым нулём и несколькими значениями возвращает skipped до обучения |

Сохранены LightGBM+XGBoost, EM, пороги сдвига/фонового класса, резерв 20%, выключатель и защита от polish. Усреднение seed и отклонённые экспериментальные методы не добавлены.

## Проверки

- Независимые before/after: настоящие модели для равных вероятностей, числовые и NA-классы, probability/auto output, составной ID с алиасом prediction, callback timeout и сохранение старого CSV.
- Плоская сборка: 12 корневых .py + официальный requirements.txt. Чистый `python -I solution.py task.md`, AGENT_LLM=off, синтетическая задача: exit 0 за 14,9 с, 800 строк, правильные ID/колонки, без пропусков. Этот короткий CLI-прогон проверяет упаковку; реальный two-stage проверен отдельными интеграционными тестами.
- `git diff --check` — без замечаний. Ключи/API не использовались, данные и логи в Git не добавлены.

Остановка кооперативная: между операциями и на итерациях adversarial LightGBM. Это не жёсткое прерывание одной операции предобработки/предсказания. При timeout готовый ответ сохраняется.
